  Plans:
    Un únic Premium amb les mateixes funcionalitats en totes les periodicitats.
    • Mensual:    39€/mes
    • Trimestral: 33€/mes (99€/3 mesos, estalvi 72€/any → -15%)
    • Anual:      29€/mes (348€/any, estalvi 120€/any → -25%)
    • Trial:      14 dies gratuïts

  Panell del bar:
    • Configuració → Canviar subscripció → periodicitat → confirmació.
    • Els locals isTestData simulen el canvi només durant la sessió:
      no creen checkout, no canvien Stripe i no modifiquen dades de facturació.
    • Els callables també rebutgen facturació real per a locals de prova.
    • Els comptes actius canvien el cicle amb prorrateig; les altes obren
      Checkout i no es presenten com a pagades abans de la confirmació.
    • Es comprova l'estat en recuperar l'app després de tornar de Stripe.
      Una fallada de consulta NO equival a una subscripció inactiva.

  Sincronització:
    • Stripe és la font de l'estat i del preu actual. Les metadades antigues
      no substitueixen el price_id del producte contractat.
    • active i trialing habiliten Premium; els estats inactius el retiren.
    • El període es llegeix de l'element de la subscripció (Stripe SDK 20).
    • El webhook llegeix la subscripció actual i actualitza barOwners/bars
      en una transacció. Ignora esdeveniments anteriors als ja processats.
    • Una subscripció existent no pot crear un altre checkout paral·lel.

  Aquests canvis requereixen desplegar explícitament els callables de
  facturació i stripeWebhook. Cal configurar els tres STRIPE_PRICE_* i els
  secrets segons els passos següents. Canviar la UI no activa Stripe ni
  configura aquests valors automàticament.

╔═══════════════════════════════════════════════════════════════════════╗
║  2. ON OBTENIR ELS SECRETS DE STRIPE                                  ║
╚═══════════════════════════════════════════════════════════════════════╝

  A) STRIPE_SECRET_KEY
     ─────────────────
     1. Ves a https://dashboard.stripe.com
     2. Registra't o inicia sessió
     3. Al dashboard, fes clic a "Developers" (menú lateral esquerre)
     4. Clica la pestanya "API keys"
     5. Copia la "Secret key" (comença per sk_test_... en mode test
        o sk_live_... en producció)

     ⚠️  IMPORTANT: En mode test pots fer proves sense cobrar de veritat.
         Només passa a sk_live_... quan tot estigui validat.

  B) STRIPE_WEBHOOK_SECRET
     ──────────────────────
     1. A Stripe Dashboard → Developers → Webhooks
     2. Clica "Add endpoint"
     3. URL del webhook:
        https://europe-west1-trobar-1123f.cloudfunctions.net/stripeWebhook
     4. Events a escoltar (selecciona aquests):
        • checkout.session.completed
        • customer.subscription.created
        • customer.subscription.updated
        • customer.subscription.deleted
        • invoice.paid
        • invoice.payment_failed
     5. Clica "Add endpoint"
     6. Un cop creat, clica a l'endpoint → "Signing secret" → "Reveal"
     7. Copia el valor (comença per whsec_...)

  C) STRIPE PRICE IDs (preus dels plans)
     ────────────────────────────────────
     1. A Stripe Dashboard → Products
     2. Clica "Add product"
     3. Crea el producte "troBar Premium"
     4. Afegeix 3 preus recurrents:
        • Mensual:    39€/mes    → recurring, monthly
        • Trimestral: 99€/3 mesos → recurring, every 3 months
        • Anual:      348€/any   → recurring, yearly
     5. Copia els Price IDs de cadascun (comencen per price_...)
     6. Aquests IDs s'han de configurar com a variables d'entorn
        (veure secció 3)


╔═══════════════════════════════════════════════════════════════════════╗
║  3. CONFIGURAR SECRETS A FIREBASE                                     ║
╚═══════════════════════════════════════════════════════════════════════╝

  Pas 1: Configurar els secrets encriptats
  ─────────────────────────────────────────
  Obre un terminal a la carpeta del projecte i executa:

    firebase functions:secrets:set STRIPE_SECRET_KEY
    → Enganxa la sk_test_... o sk_live_...

    firebase functions:secrets:set STRIPE_WEBHOOK_SECRET
    → Enganxa el whsec_...

  Pas 2: Configurar els Price IDs
  ────────────────────────────────
  Configura les variables d'entorn de Functions (functions/.env.<project-id>
  o l'entorn de desplegament autoritzat):

    STRIPE_PRICE_MONTHLY
    STRIPE_PRICE_QUARTERLY
    STRIPE_PRICE_ANNUAL

  No incorporis IDs ni secrets reals al codi. functions:config:set amb
  stripe.price_* no alimenta process.env.STRIPE_PRICE_* en aquest backend.
  Es comproven imports, EUR, recurrència i estat actiu del preu. Sense
  configuració, Checkout i change-plan fallen explícitament.
  STRIPE_ALLOW_LIVE_BILLING=true només després d'autoritzar activació live.
  STRIPE_ALLOWED_RETURN_ORIGINS admet orígens HTTPS addicionals explícits;
  per defecte es permeten trobar.cat i www.trobar.cat.

╔═══════════════════════════════════════════════════════════════════════╗
║  5. FLUX DE PAGAMENT PAS A PAS                                        ║
╚═══════════════════════════════════════════════════════════════════════╝

  A) PRIMERA SUBSCRIPCIÓ (Checkout)
     1. L'usuari es registra via web-app (ja implementat)
     2. Es desa l'esborrany pending_checkout (isActive=false) i s'obre
        createCheckoutSession amb el billingCycle triat, en la mateixa acció
     3. Stripe obre una pàgina de checkout amb targeta de crèdit
     4. L'usuari paga (o inicia trial de 14 dies)
     5. Stripe envia event checkout.session.completed al webhook
     6. El webhook actualitza Firestore:
        - barOwners/{uid}.stripeSubscriptionId = sub_XXX
        - barOwners/{uid}.subscriptionStatus = estat actual (active/trialing)
        - bars/{barId}.status = "registered", isActive = true
        - bars/{barId}.tier = "premium"

  B) CANVI DE PLA
     1. L'usuari toca un cicle diferent al toggle (Configuració)
     2. S'obre el modal de confirmació amb detalls (pla actual → nou)
     3. L'usuari confirma
     4. Es crida changeBillingCycle(newCycle) → Cloud Function
     5. La Cloud Function actualitza la subscripció a Stripe amb prorrateig
     6. Stripe envia customer.subscription.updated al webhook
     7. Firestore s'actualitza amb el nou cicle

  C) ELIMINACIÓ DE COMPTE
     1. L'usuari toca "Eliminar el compte"
     2. S'obre modal pas 1: Advertència amb llista de conseqüències
     3. L'usuari toca "Sí, continuar"
     4. Pas 2: Ha d'escriure "ELIMINAR" per confirmar
     5. Es crida deleteAccount() (AuthContext):
        a) cancelSubscription() → Cloud Function → Stripe cancel
        b) deleteUserProfile() → Elimina docs de Firestore
        c) auth.currentUser.delete() → Elimina compte Firebase Auth
     6. L'usuari és redirigit automàticament al mapa (onAuthStateChanged)

  D) PAGAMENT FALLAT
     1. Stripe intenta cobrar però falla (targeta caducada, etc.)
     2. Stripe envia invoice.payment_failed al webhook
     3. El webhook consulta l'estat actual Stripe (p. ex. past_due/unpaid)
        i retira Premium quan ja no és active/trialing
     4. El dashboard mostra el badge "INACTIU" en vermell
     5. L'usuari ha d'actualitzar les dades de pagament via Stripe

╔═══════════════════════════════════════════════════════════════════════╗
║  7. DOCUMENTS DE FIRESTORE IMPLICATS                                  ║
╚═══════════════════════════════════════════════════════════════════════╝

  barOwners/{uid}:
    ├── stripeCustomerId:     "cus_XXXX"
    ├── stripeSubscriptionId: "sub_XXXX"
    ├── subscriptionStatus:   estat Stripe ("active", "trialing", "past_due", "unpaid", "canceled", etc.)
    ├── billingCycle:         "monthly" | "quarterly" | "annual"
    ├── currentPeriodEnd:     segons Unix (de l'element Stripe)
    ├── trialEnd:             segons Unix o null
    ├── lastStripeEventCreated: segons Unix
    ├── cancelledAt:          Timestamp (si cancel·lat)
    └── checkoutAttempt / checkoutExpiresAt: reserva idempotent de Checkout

  stripeEvents/{eventId}: registre privat de webhooks ja processats.

  bars/{barId}:
    ├── tier:     "premium" | "free"
    ├── premium:  true | false
    └── billing:  "monthly" | "quarterly" | "annual"
